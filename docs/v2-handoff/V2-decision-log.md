# V2 背景決策收集

這一份是同意玩家在正常對局裡自動留下的決策資料。它沿用既有的教 AI 帳號、匿名識別、上傳與刪除，不另外做一套牌譜系統。

收集完成只代表資料進了這個玩家自己的帳號。它不會訓練模型，也不會讓目前的對戰 AI 變強。賽後手動「標記 / 教 AI」仍是另一種示範，不會寫進這份 JSONL。

## 同意

開關文字是「提供對戰紀錄改善 AI」。預設關閉，選擇記在這個瀏覽器的 `ua-v2-coach-consent`。

- 關閉時不組決策、不送網路。尚未上傳的本機佇列會立刻清掉。
- 開啟後，單人對電腦與線上對戰都在背景收集。
- 線上對戰每個玩家各自決定。只記錄已同意玩家本人、而且伺服器已經接受的操作。
- 需要登入。匯出與刪除只處理這個帳號自己的資料。

## 什麼會留下

引擎成功接受操作之後才記一筆。點卡片、開視窗、取消選取、非法操作、同一筆網路重送，都不是新決策。

操作前的公開視圖與本人當時看得到的選牌會先擷取。AI 操作使用既有的示範格式 `ua-v2-coach-demo-v1`，不會進玩家決策表，也不會出現在 JSONL。

決策類型：`play`、`move`、`raid`、`attack`、`block`、`search`、`discard`、`pay`、`effect`、`order`、`skip`、`mulligan`。無法歸類的操作是 `other`。

## 一筆決策有什麼

格式 `ua-v2-coach-step-v2`。至少包含：

- `engine`、`engineVersion`（目前 `ua-v2.0`）、`pool`
- `anonymousId`、`matchId`、連續的 `step`、`clientKey`
- `source` / `actor`（玩家決策固定是 `human`）、`channel` / `mode`（`solo` 或 `online`）、`turn`、`phase`
- `deck`：自己的牌組張數，沒有牌序
- `observation`：當時自己看得到的手牌、場面、AP、能源，以及授權檢視的牌
- `publicHistory`：公開戰鬥、觸發與公開揭示
- `legal`、`choice`、`forced`（是不是只有一個合法選項）、`decisionClass`
- `previous` 與 `chain`：串起前後步驟

線上對戰用 `engineRevision` 當去重依據，不共用雙方的對局編號。兩位玩家各自有 `m` 開頭的對局編號；同一個房間用 `k` 開頭的 `matchLink` 對照，連結值不是房間代碼。

## 對局結果

結果是單獨的標籤，格式 `ua-v2-coach-label-v2`，不放進每一步的模型輸入。

- 正常結束：`life-zero`、`unblocked-attack`、`required-draw-empty`、`finished`。`completed` 為 true，`winner` 是 0 或 1。
- 認輸：`conceded`。`completed` 為 false，仍有勝者。
- 中斷、放棄、錯誤、未完成：`interrupted`、`abandoned`、`error`、`incomplete`。`completed` 為 false，`winner` 必須是 null。這四種不是和局，也不是勝利。

## 視角

訓練輸入使用引擎公開視圖，加上這個座位已被授權看到的牌。

不包含對手隱藏手牌、未知牌序、未公開生命、未來勝敗，或能還原未知牌序的種子。勝敗只出現在對局結果。除錯重播仍走 `/api/coach/debug-replays`，JSON 與 JSONL 匯出都不會帶出重播。

## 上傳

本機佇列鍵是 `ua-v2-coach-queue-v1`。每一筆再依帳號與 `clientKey` 分開存放。決策、結束標記、示範和除錯重播在寫入時保存當時的帳號識別。決策先寫進佇列，下一步操作不等上傳，也不等另一個分頁的寫入鎖。單筆要確認寫入後才回報已排隊；空間不足時回傳未儲存，畫面顯示「紀錄尚未儲存」，對戰照常進行。舊佇列一次搬一筆，新位置讀得回才從舊佇列移除。只搬一部分時，剩下的仍可讀，重新載入後繼續搬。完成標記要等舊佇列搬完才寫上，避免兩份完整內容一起留著。入列、搬移、送出確認和撤回都在取得鎖之後才寫；拿不到鎖就延後重試，不會在逾時後照寫。同一場的連續操作仍按步驟順序保存與上傳。新增、送出成功、重試、撤回和拒絕都只更新對應的那一筆。滿 8 筆或約 1.2 秒後批次送出。送出前會再讀一次目前登入帳號，只送識別相同的列。伺服器也核對這筆識別和目前登入帳號，擋住檢查與送出之間剛好切換帳號的情況。`clientKey` 重複且內容相同時伺服器回 `duplicate: true`，不新增第二筆。已經送出成功的列會從佇列刪除，舊分頁不能把它寫回去。舊佇列裡能確認帳號的列照原順序遷入單筆儲存。歸屬不明的列和其他帳號的列留在這台裝置，暫停上傳，不刪除。斷線、401、403、500 會把目前帳號的那一筆留下並退避後再送。帳號識別不會寫進訓練內容或匯出。400、409、413 代表這筆保存不了：客戶端跳過這筆，以及同一場還排在後面的決策，結果標籤和別場的決策繼續送。已經在傳送中的那一步不能用返回上一步收回。復原尚未寫入的步驟時，先在這場的紀錄狀態取消它，替代操作沿用撤回後的編號；鎖放開後只留下替代的那一筆。較晚完成的寫入或撤回只更新原本那一場。快照帶上尚未寫入的步驟，重整後先補存，再上傳後面的操作。補存還沒寫進佇列時，新操作先暫存，等那筆落地或確定失敗後才編號。無法恢復、也不在已確認連續紀錄裡的步驟會顯示「紀錄尚未儲存」，下一筆從已確認的編號接續。伺服器已經收下的步驟不會重新佔用編號；內容相同的重送仍是 duplicate。續局對帳還沒完成時，新操作先依序暫存，等伺服器已收筆數和本機待傳步驟核對後才編號、接上前一筆並入列。伺服器確定沒有這場紀錄時從已確認的編號接續；對帳失敗或逾時則保留暫存並重試，不當成空紀錄。上傳確認後把已接受的步驟寫進可恢復的進度，延遲回覆只更新原帳號、原場次。關閉紀錄只清掉尚未上傳、且依同意應清除的資料，已確認的步驟與前一筆連結留著；若關閉時有一筆正在送出，重新開啟後先確認它是否已被接受，再決定下一個編號。關閉期間的操作不收集。關閉後，已經送出的那一輪不再自動重試，即使立刻重新開啟也不重送已撤回的內容。已經在途的請求若成功，只確認原帳號、原場次的編號。重新開啟時若那一筆還沒確認，先核對伺服器有沒有收下再決定下一個編號；請求逾時或結果不明時，新操作先暫存。關閉紀錄時用舊快照續局，會留下待對帳狀態，重新同意後才查伺服器；確認前的新操作先暫存。伺服器進度超前時，下一筆的 previous 與 chain 指向伺服器最後一筆。線上對戰關閉紀錄時，在途的步驟先依原帳號、場次、房間與座位對帳，再決定下一個編號；舊的同意版本不會重試。對帳還沒回來時，新操作依序全部暫存，確認後再連續編號；同一個 engineRevision 不重複暫存，再次關閉會清掉該輪還沒送出的暫存。單人分頁變更同意版本時，線上分頁用保留的帳號、場次與步驟對帳，即使共用佇列已被清掉。不同帳號、場次、房間與座位的對帳互不卡住，舊回覆只更新原本那一筆紀錄。

線上房間視圖由伺服器在同一份回應帶上當時的帳號、房間、座位和修訂號。`arm()` 在送出操作前收下這份身分與手牌；延遲回覆沿用它，不再事後查登入帳號。結束標記使用該次事件原本綁定的帳號、房間與座位。延遲送達的事件仍屬於原本的帳號。另一個帳號之後進同一房間或認輸，使用它自己的場次。`prepare()` 不會因為房間編號相同就沿用上一個帳號的場次。本機房間索引是「帳號、座位、房間編號」。歸屬不明的線上步驟和結束標記暫停保存。

單人續局的開局設定和進度各按帳號分開存放。沒有快照才開新局；快照屬於其他帳號，或內容讀不出來時，保留原檔、不覆蓋。舊分頁重新開局、替換模型或寫入進度之前，會核對目前帳號是不是本場已綁定的帳號。身分不同就留在原畫面，提示回到對戰設定，由目前帳號另開一局，不改兩邊的開局、進度或模型。暫時無法確認身分時，不重開也不覆寫。帳號服務暫時沒有回應時，可以從設定頁開一場不記錄的訪客練習，已綁定帳號的快照留待身分恢復後再讀。模型 API 在同一份回應帶回伺服器確認的帳號；與本場不符就改用困難 AI，並顯示原因，不把另一個帳號的權重寫進這份快照。

查看、匯出 JSON、匯出 JSONL、刪除單場與刪除全部，都在 `/coach.html`。JSONL 路徑是 `GET /api/coach/export.jsonl`。

## 合成示例

`docs/v2-handoff/examples/ua-v2-decision-sample.jsonl` 是用公開測試牌組與固定種子在本地生成的三行 JSONL：清單、一筆起手保留、一筆中斷結果。它不是任何玩家的上傳資料，檔案裡沒有帳號、種子或對手手牌。

## 實測

同一個 40 步對局、各跑 5 輪。關閉收集只做引擎操作；開啟收集多做決策組裝與 JSON 序列化，不包含網路。

| 項目 | 結果 |
| --- | --- |
| 關閉收集 | 18.78 ms / 40 步 |
| 開啟收集 | 24.15 ms / 40 步 |
| 多出來的時間 | 5.37 ms，約 0.27 ms / 次真人決策 |
| 資料量 | 約 2,649 bytes / 次真人決策 |

瀏覽器裡，第一次關閉收集的起手點擊含畫面繪製是 16.7 ms；同一場重新開局、開啟收集後的起手點擊是 5.7 ms。開啟收集沒有讓這次點擊變慢。線上對戰從按下「保留這 7 張手牌」到本機佇列出現這筆已接受決策是 268 ms，時間主要在對戰伺服器回覆，不是在上傳。

瀏覽器驗收同時確認：畫面上的 7 張手牌與紀錄手牌一致；點卡片不會產生決策；未同意的線上對手按下保留後，本機佇列與該帳號匯出都沒有這筆決策。
