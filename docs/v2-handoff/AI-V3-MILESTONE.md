## 玩法

單人對戰設定頁有「完整回合搜尋預覽」，寫入 `localStorage` 鍵 `ua-ai-v3-preview`。對局中可按「關閉搜尋預覽」回到這場選擇的難度。困難是 `hard-search-2`。

電腦回合把 actor 可見局面做成 belief world，交給 module Worker。`requestId`、`stateVersion` 或 `actor` 不符就丟棄；回來的 action 必須重新出現在當下的合法列表。Worker 逾時（700ms）時，同一頁內用較小預算再搜一次，仍不合法就回到 `chooseProgressSafeAiAction`。

搜尋邊界是真正的決策，不是把舊 depth 常數加大。單選動作直接採用。起手調度與順序類 pending 交給凍結基準。其餘候選用牌型先驗縮束，再對當前回合與對手下一回合做 minimax。強制的階段推進與戰鬥結算不佔決策配額。相同規則狀態共用 transposition。每一步都是引擎的合法 action。

抽樣世界只用自己剩餘張數、公開資訊與合理對手牌型。真實對手手牌、牌序、LIFE 與 RNG 不會進入 Worker。模擬對手只看它自己的可見局面。

## 重現

```bash
node --test tests/ai-v3-search.test.mjs tests/ai-v3-strategy.test.mjs
npm test
npm run worker:build
AI_V3_GAMES=3 AI_V3_STEPS=400 AI_V3_MODES=beam AI_V3_DEV_SEED=8100 node scripts/ai-v3-benchmark.mjs
AI_V3_SPLIT=final AI_V3_GAMES=3 AI_V3_STEPS=400 AI_V3_MODES=beam AI_V3_FINAL_SEED=5000 node scripts/ai-v3-benchmark.mjs
```

開發種子從 `AI_V3_DEV_SEED`（預設 8100）起，只用來找失敗模式。最終種子從 `AI_V3_FINAL_SEED`（預設 5000）起，需 `AI_V3_SPLIT=final`。最終種子沒有用來改任何常數。

本地頁面：`python3 -m http.server 8000 --directory dist`，打開 `/universal-v2-preview.html`。

## 已測到的決策差異

`tests/fixtures/ai-v3-mistakes.json` 的 `bleach-energy-instead-of-blocker` 是決策錯誤，不是規則錯誤。

局面：先手生命 1，手牌是 0 費 1000 BP 的茶渡 泰虎（`BLC-1-042`），對手前線有可行動的阿散井 恋次（`BLC-1-045`，2000 BP）。Q34：阻擋者 BP 較低時雙方都不退場，也不扣生命。放到前線，回合結束會回復並擋下攻擊。放到能量區則擋不住。

`hard-search-2` 打到能量區。`ai-v3-beam-1` 打到前線。同一測試也確認未阻擋的致死攻擊會被選走，以及非法 action 會被拒絕。

五副合法 50 張牌組：BLEACH、Sword Art Online、Solo Leveling、Steins;Gate、進擊的巨人。後兩部不在舊的五作品統計裡。

合法性與策略正確率分開算。`tests/ai-v3-search.test.mjs` 的 100 個主要／攻擊階段多選局面，每個作品 20 個，結果必須在合法列表中，而且不能在另有非立即敗北走法時選立即敗北。這次是 100/100，五個作品都是 20，問題 0。`tests/ai-v3-strategy.test.mjs` 另有五個寫死預期答案的局面，不計入那 100 個：

| 局面 | 預期 | 結果 |
| --- | --- | --- |
| 斬殺 | 無人阻擋、對方生命 1 時攻擊 `BLC-1-043` | 通過 |
| 必要阻擋 | 自己生命 1 時擋下對方攻擊，不選放棄 | 通過 |
| AP 回復 | `BLC-4-059` 把 REST 的 AP 轉為 Active，接著突襲 `BLC-1-053` | 通過 |

另外一則是從整場失敗看出來的：場上已有一張能源、前線是空的時候，下一張 0 費角色打到前線。這則也通過，同樣不計入 100 個合法性檢查。

## 四項搜尋缺陷

修正前的數字來自同一套引擎局面。修正後由測試鎖定，下面的「修正後」是這輪重新量到的。

1. 狀態鍵。同一張 `BLC-1-046` 的 +500 BP，選 1500 BP 的角色得到 `[2000,2000]`，選 2000 BP 的角色得到 `[1500,2500]`，舊的 `stateKey` 相同。修正後的鍵包含增益、能力使用、pending 內容、突襲底板與層、延遲效果、雙方手牌、牌序、LIFE 順序與 AP 是否 Active。引擎結算後的兩條線鍵不同；共用同一張 transposition 時，2500 BP 那條對上 2500 的牆，分數高於兩張 2000。能力發動前與發動後的鍵也不同。`SLG-1-042` 經引擎排進 `retireAtMainEnd` 之後，鍵會變。突襲把 `BLC-1-051` 壓進牌疊之後，鍵也會變。
2. prior。安全候選（`next`、skip、decline、`uid null`）被插到第一個，prior 直接取第一個。合法的 `BLC-1-042` 出牌存在時，選到的是 `{type:'next'}`。修正後保留候選與策略排序分開：prior 走 `rankLegal` 的最高分，不再走束寬列表的第 0 個。同一個只有這張可出的手牌，prior 會出牌。
3. 先後手。舊迴圈用 `first===0 ? [challenger, baseline] : [baseline, challenger]`，換座位時連先手一起換，兩場都是新版先手。修正後先手座位與新版座位是 2×2。每個種子、每個先手都用同一副牌、同一個種子、同一手起手，只換兩邊的 AI。最終 60 場是 30 場先手、30 場後手。
4. 節點預算。`nodes=48`、`worlds=2` 時，每個候選至少分到 12 個節點，4 個候選乘 2 個世界是 96；實測用了 91。修正後所有候選與抽樣世界共用一個池，成功的 dispatch 才計數，含戰鬥分支與強制推進。同一局面、`worlds=2`、`ms` 不設上限，新版用了 48。凍結的 `hard-search-2` 在同一局面、同樣 `nodes=48` 用了 34。基準比較改為直接呼叫 `chooseStrengthenedHardAction`，兩邊都傳 `{nodes:48, ms:40}`。ISMCTS 也吃同一個池，不再每個迭代自保 8 個節點。

## 同預算完整對局

兩邊都是 `nodes=48`、`ms=40`、`beam=4`、雙方各 2 個決策。每作品 3 個種子、每個種子 4 場（先手 0/1 × 新版座位 0/1）。同一對的兩場座位共用種子與起手。400 步上限。延遲只計合法選項多於 1 的決策。完成率是生命歸零的終局，不是步數上限。配對差是「新版在兩個座位的勝場平均，減 0.5」，bootstrap 1000 次取第 25 與第 974 個。

較早的 16 步延遲表還在 `audit/ai-v3-dev-benchmark.json`。那次沒有終局，不能和下面的勝率放在一起。

開發種子 8100–8102 修正四項缺陷之後、補上前線信用之前：60 場全部終局、非法 0、備援 0，新版 0 勝。動作裡沒有攻擊、沒有真正的阻擋，每場都是對方生命 7、自己 0。失敗模式是束寬被能源出牌占滿，淺層搜尋又看不到下一回合的攻擊，所以角色一直不進前線。

依這個模式改了兩件事，沒有對單一種子調常數：束寬保留一張前線出牌；場上已有至少一張能源、前線還沒有角色時，根節點給前線出牌 +18。信用只加在這個出牌動作上，不寫進場面評價，避免之後為了守住信用而拒絕擋刀。這張牌若同時能突襲，就不加信用，突襲仍走自己的搜尋分。

改完後重跑同一組開發種子（2026-11-05 17:49，台北時間）。60 場仍是 0 勝，但已經會進前線、攻擊與阻擋。逐作品新版留下的對方生命平均是 BLEACH 4.67、Sword Art Online 4.75、Solo Leveling 5.92、Steins;Gate 5.25、進擊的巨人 6.58。原始對局在 `audit/ai-v3-dev-before-strategy.json` 與 `audit/ai-v3-dev-after.json`。

## 瀏覽器

Chrome headless 打開本機預覽頁。核取方塊一開始未勾、`localStorage` 沒有開啟值。勾選後寫入 `1`，難度設為困難、電腦先手，進入對戰頁。電腦思考時 `document.body.dataset.aiPolicy` 是 `ai-v3-beam-1`，頁面出現 Worker，沒有未捕捉例外。關掉預覽並按下一個階段之後，政策回到 `hard-search-2`，按鈕變回「完整回合搜尋」。

`npm run worker:build` 已寫出 gitignore 的 `worker/dist/index.mjs`。esbuild 對既有重複鍵的警告還在，建置本身成功。

## 未達標

- 最終種子的配對差是 -0.5，區間也是 -0.5 到 -0.5。新版會進前線、攻擊和阻擋，仍然每一場都輸給凍結的 `hard-search-2`。這不是戰力提升。
- 價值網路沒有訓練。先驗只在呼叫端傳入 v4 權重時生效。
- 瀏覽器 Worker 路徑先送一個已抹除隱藏資訊的世界，Worker 內再以 `worlds:1` 搜尋。同預算表裡的 belief 是行程內 2 個世界，兩者不要看成同一個路徑。
- 不合併、不部署正式站。預覽仍是預設關閉，關閉後回到這場選擇的難度。
